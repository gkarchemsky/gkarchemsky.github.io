{%- comment -%} Every post, grouped by year, in a sticky rail. The reason this exists: /blog/ pages at 10, so from the 11th post onward the older ones are reachable only by paging, searching, or guessing a tag. That is fine at 6 posts and hostile at 50 — the reader who half-remembers a post about one decoder has no way to scan for it. Project Zero solves this with exactly this component, and it is the single cheapest navigation win a research blog has: the whole archive, one click from anywhere, no query to compose. Complete on purpose — no pagination, no "show more". A list of titles is a few bytes each, and the value is precisely that nothing is hidden. The current year is open; older years collapse into
, so the rail stays scannable as the archive grows. `open` on the first group is set by forloop.first rather than by comparing to "now", so a year with no posts yet does not open an empty group in January. Usage: {% include archive-rail.html %} inside a .page-shell {%- endcomment -%} {%- comment -%} `posts` scopes the rail to a subset — /blog/ passes everything that is not a CTF write-up, /ctf/ passes only the CTF ones, the home page passes nothing and gets all of them. Not `include.posts | default: site.posts`: Liquid's `default` treats an empty array as empty and would silently swap in the full list, so a section with no posts yet would show every post in the site. An explicit test is the only safe form here. {%- endcomment -%} {%- if include.posts -%} {%- assign rail_posts = include.posts -%} {%- else -%} {%- assign rail_posts = site.posts -%} {%- endif -%} {%- assign posts_by_year = rail_posts | group_by_exp: "p", "p.date | date: '%Y'" -%} {%- if posts_by_year.size > 0 %}
